# Part C video walkthrough

Target length: 8–12 minutes.

## 1. State the problem (1 minute)

Explain that an ML engineer often needs to compare training configurations,
but an unconstrained agent could run forever, change the objective, or leave no
reproducible evidence. Part C turns that workflow into a bounded autoresearch
tool.

## 2. Show the repository (1 minute)

Show `benchmark/train.py`, `benchmark/autoresearch.py`,
`plugins/autoresearch.mjs`, the tests, and the generated-results directory.
Point out that the benchmark uses a deterministic synthetic nonlinear dataset,
so the demonstration does not require a download or secret.

## 3. Explain the benchmark (2 minutes)

Walk through the baseline: a degree-one linear model with a fixed learning
rate, epoch count, and regularization value. Then show the candidate pool,
which changes feature degree and training hyperparameters. The objective is to
minimize validation MSE; the best candidate is accepted only when its score is
lower than the current best.

## 4. Explain the safety boundary (1 minute)

Show the plugin validation: `maxTrials` is restricted to 1–8, `seed` is
restricted to a finite integer range, the Python process has a 30-second
timeout, the dataset is generated locally, and the plugin accepts no arbitrary
commands, paths, or code from the model.

## 5. Run the offline demo (1 minute)

From this directory run:

```bash
npm run demo
```

Show the baseline MSE, the improved best MSE, the improvement percentage, and
the JSON artifact under `results/`.

## 6. Run the tests (1 minute)

```bash
npm test
```

Point out the reproducibility, improvement, budget, and JSON serialization
tests.

## 7. Show DeepSeek Harness integration (2 minutes)

Generate the Cordis overlay:

```bash
npm run generate:patch
```

From the official DeepSeek Harness checkout, start the Web UI with the
generated patch:

```bash
pnpm dsh web --patch ../CMPE297-Assignment2/part-c-autoresearch/patches/part-c.generated.cordis.yml
```

Run the prompts in `prompts/demo-prompts.md`. Capture the tool call, structured
result, trajectory, and saved artifact. For the creator-mode prompt, show the
agent turning the experiment result into a verified Markdown report.

## 8. Close with limitations (1 minute)

Explain that this is a teaching harness, not a production ML platform. A
production system should isolate workloads in containers, sign datasets and
code, track dependencies, use stronger resource quotas, and evaluate on a
held-out benchmark that is not generated by the runner itself.
